# Query validation status

Generated by `scripts/validation-status.py` from the header of each query. Do not edit by hand: change the header of the query and run the script (CI fails if this page is out of date).

**147 queries**: 126 validated, 6 partly validated, 15 NOT VERIFIED, 0 with no status stated. The KQL Library counts 47 blocks here because a Q5a, Q5b and Q5c are separate blocks (the README counts them as one query).

| Status | Meaning |
|---|---|
| Validated | The header says the query ran or compiled on a tenant or workspace, gives the result it returned, or (KQL Library) the file has a last-validation date. Read the header for what exactly was checked. |
| Partly validated | The header says one branch of the query ran and another is NOT VERIFIED (for example the app-role events ran and the consent events did not). Read the header. |
| NOT VERIFIED | The header says it has not run against real data, usually because the table, event or preview capability is missing in the validation tenant. |
| Not stated | The header says nothing. Treat it as not verified until it does. |

**Runs in** comes from the code: `Timestamp` means Defender Advanced Hunting, `TimeGenerated` means Sentinel (Log Analytics), `resources` or `authorizationresources` means Azure Resource Graph, and Mixed means both columns appear, so read the header before pasting. **Preview** means the header mentions a preview capability.
