## When to use

- As the first visibility control before implementing DLP or sensitivity labels
- When there is no auditing of AI agent interactions in the tenant
- Prerequisite for correlation with Sentinel: AI Hub generates events that the
  Purview connector forwards to the workspace

## What AI Hub captures

- Prompts sent by users to M365 Copilot and Copilot Studio agents
- Responses generated by the agents
- Files and data referenced during the interaction
- Sensitive information types detected in prompts/responses
- User, timestamp, involved agent

## Known limitation

AI Hub does not capture interactions from autonomous agents (non-human triggered).
For agents operating without user interaction, coverage is partial.
Complement with Foundry logs and Sentinel analytics.

## Workflow

### Step 1 — Enable AI Hub in the Purview Compliance Portal

```
Microsoft Purview Compliance Portal (compliance.microsoft.com)
→ Solutions → AI Hub (preview)
→ Get started → Enable AI Hub
```

If it does not appear in the menu: verify the M365 E5 Compliance or Purview E3 license.

### Step 2 — Configure which interactions to capture

```
AI Hub → Settings → Data capture
```

Options:
- **M365 Copilot interactions**: prompts and responses in Copilot for M365
- **Copilot Studio interactions**: conversations with Copilot Studio agents
- **Third-party AI apps**: requires an additional connector

Enable everything available in the tenant.

### Step 3 — Review the activity dashboard

```
AI Hub → Overview
```

Available metrics:
- Total interactions (last 30 days)
- Sensitive information types detected
- Top users by interaction volume
- Most-used agents

### Step 4 — Configure AI Hub policies

```
AI Hub → Policies → Create policy
```

Available policy types:
- **Sensitive data**: alert when PII, financial data, etc. is detected
- **Prompt injection indicators**: patterns of malicious instructions
- **Restricted topics**: topics the agent must not address

### Step 5 — Connect to Sentinel

AI Hub generates events in the `MicrosoftDataLossPrevention` and `PurviewAuditLog` tables.
Verify the Purview connector is active in {workspace-name} and that events are flowing.

```kql
// Verify event flow from AI Hub
PurviewAuditLog
| where TimeGenerated > ago(24h)
| where Workload has "Copilot"
| summarize count() by OperationName
```

## Verification

- [ ] AI Hub enabled and visible in the Compliance Portal
- [ ] Data capture active for M365 Copilot and Copilot Studio
- [ ] Dashboard shows interactions from the last 7 days
- [ ] At least one AI Hub policy created
- [ ] Events visible in Sentinel (`PurviewAuditLog` has recent rows)

## Implementation notes

- Verify the Purview Audit connector is active in Sentinel — without it, `PurviewAuditLog` will have no data for the monitoring queries
- AI Hub is in preview — validate functionality against Microsoft Learn documentation before writing it into production runbooks
- If AI Hub is unavailable in the tenant: use `MicrosoftDataLossPrevention` as an alternative table to correlate interactions
